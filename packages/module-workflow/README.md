# module-workflow

BPM-движок платформы: шаблоны процессов, версионируемые графы (start/userTask/gateway/serviceTask/
asyncTask/end), запущенные экземпляры, визуальный редактор на React Flow. Домен (HR, будущие
assessment/appraisal и т.п.) в движок не встроен — подключается извне через `WorkflowRegistry`
(делегаты исполнителя, валидаторы, автоматика) и `WorkflowEngine` (программный запуск/продвижение
процессов из других модулей).

Документы в `docs/` написаны по прочтению исходников `src/` и являются источником истины наравне с
кодом. История решений и первоначальные намерения — в `ref/plans/*workflow*`
в корне репозитория.
Где план и код расходятся — код побеждает.

## Быстрые факты

- Роуты: `/api/workflows/*` (требуют аутентифицированного пользователя).
- Точки расширения: `WORKFLOW_REGISTRY_TOKEN` (`'workflow-registry'`), `WORKFLOW_ENGINE_TOKEN`
  (`'workflow-engine'`) — резолвятся через `context.services.resolve(...)`, экспортируются из
  `@amplicada/module-workflow/contracts`.
- Визуальный редактор: `/admin/workflows/:id/editor`. Таймлайн процесса: `/admin/workflows/processes/:id`.
- Сегодняшние потребители: `module-hr` (делегат `fixed-assignee`), `module-hr-request` (запускает и
  продвигает процессы in-process, оборачивая их своими доменными роутами `/api/hr-requests/*`).
- Модуль должен грузиться **до** любого потребителя — порядок задаётся массивом в
  `bootstrap()` (`apps/api/src/index.ts`), не декларативно.
