# Admin — файловый менеджер хранилища

Страница `/admin/storage` — файловый менеджер S3-совместимого хранилища в духе Windows
Explorer: дерево папок, адресная строка, поиск, мультивыбор, сортировка, вид списком и
плиткой, предпросмотр и операции — создать папку, переименовать, переместить, скачать,
удалить. Директорий в S3 нет — «папка» здесь это общий префикс ключей до
следующего `/` (`CommonPrefixes`), см. `listObjects` в
[platform-core storage](../../../platform-core/docs/reference/storage.md).

Доступ — только аутентифицированная сессия (тот же `preHandler`, что у остальных
admin-роутов). Отдельных прав на объекты нет.

## HTTP API

Все роуты — под `/api/admin`.

| Метод и путь | Что делает |
|---|---|
| `GET /storage/config` | Возможности страницы: `{ editEnabled }` |
| `GET /storage/objects?prefix=` | Листинг одной «папки»: `{ prefix, prefixes, objects }` |
| `POST /storage/objects?prefix=` | Загрузка файла (multipart-часть `file`) в папку; тело — потоком |
| `POST /storage/folder?prefix=` | Создание папки: тело `{ name }`, пустой объект-маркер `${prefix}${name}/` |
| `PUT /storage/objects?key=` | Сохранение текста в существующий объект; JSON `{ content }` — только при `STORAGE_EDIT_ENABLED=true` |
| `POST /storage/move` | Перемещение/переименование: тело `{ keys, destination, name? }` → `{ moved }` |
| `DELETE /storage/objects` | Пакетное удаление: тело `{ keys: string[] }` → `{ deleted }` |
| `DELETE /storage/folder?prefix=` | Рекурсивное удаление папки; ответ `{ deleted }` — число объектов |
| `GET /storage/objects/download?key=` | Скачивание (`Content-Disposition: attachment`), `Range` → `206` |
| `GET /storage/objects/view?key=` | Просмотр в браузере (`inline`), `Range` → `206` |

Ключ объекта — query-параметр `key`, не сегмент пути: `:key` в Fastify не матчит слэши,
то есть на ключах вида `learning/pkg/index.html` роут отвечал бы 404. `prefix` нормализуется
к виду с `/` на конце (`foo` → `foo/`), иначе листинг захватил бы `foobar.txt`.

`prefix` без значения — корень бакета. `DELETE /storage/folder` без `prefix` отвечает
`400`: пустой префикс означал бы удаление всего бакета.

`DELETE /storage/objects` принимает ключи только телом запроса: прежняя форма `?key=`
удалена, одиночное и пакетное удаление — теперь один роут. Пустой список — `400`.

`PUT /storage/objects` принимает JSON `{ content: string }` (лимит тела — 8 МБ) и сохраняет
текст в уже существующий объект: ключ — в `key`, существование проверяется `HEAD` (иначе `404`,
новый объект не создаётся), прежний `Content-Type` сохраняется. Ошибки: `400` — нет ключа или
не строковый `content`, `404` — объекта нет.

### Флаг правки: `STORAGE_EDIT_ENABLED`

Правка текста выключена по умолчанию и включается переменной окружения
`STORAGE_EDIT_ENABLED=true` при старте API. Пока флаг не включён, роут `PUT` **не
регистрируется вовсе** (`404`), а не отвечает `403`; `GET /storage/config` отдаёт фронту
`{ editEnabled }`, и превью открывается только для чтения. Скрывать одну кнопку в UI
недостаточно — эндпоинт остался бы доступен любой аутентифицированной сессии.

### Типы ответов

`GET /storage/objects`:

```json
{
  "prefix": "learning/",
  "prefixes": ["learning/pkg-a/", "learning/pkg-b/"],
  "objects": [
    { "key": "learning/index.json", "size": 1234, "etag": "\"...\"", "lastModified": "2026-09-18T10:00:00.000Z" }
  ]
}
```

Объекты-маркеры папок (ключи с `/` на конце) в `objects` не попадают — они видны как папки
в `prefixes` и удаляются вместе с папкой.

`GET /storage/objects/download` и `/view` отдают `Content-Disposition`, `Accept-Ranges:
bytes`, `X-Content-Type-Options: nosniff`; при наличии `Range` — `206` с `Content-Range`.
Для активных типов (`image/svg+xml`, `text/html`, XML) просмотр дополнительно получает
`Content-Security-Policy: sandbox`, чтобы чужой документ не исполнился на нашем origin.

## Операции

Семантика операций живёт в `src/backend/routes/storage.ts`; фронт только собирает запросы.

### Создание папки

`POST /storage/folder?prefix=` тело `{ name }` кладёт пустой объект-маркер
`${prefix}${name}/` с `Content-Type: application/x-directory`: директорий в S3 нет, и без
маркера пустая папка не появилась бы в листинге. Имя — ровно один сегмент: пустое, `.`,
`..`, содержащее `/` или `\`, длиннее 255 символов — `400`. Если папка уже существует
(маркер или хотя бы один объект под префиксом) — `409`; существующая папка не перезаписывается.

### Перемещение и переименование

`POST /storage/move` тело `{ keys, destination, name? }` → `{ moved }` (число
верхнеуровневых элементов, не объектов поддерева). Перемещение в S3 — это copy + delete:
переименовать префикс одним запросом нельзя. Для файла: копирование в `destination` + имя,
затем удаление исходного ключа. Для папки (ключ с `/` на конце): рекурсивный листинг
поддерева, копирование каждого объекта, маркер цели (чтобы пустая папка осталась папкой) и
удаление старых объектов и маркера. `destination` нормализуется к виду с `/` на конце;
`'/'` — корень бакета. `name` допустим только при одном ключе и означает переименование:
для папки цель — `${destination}${name}/`. В UI переименование вызывается через `F2` или
двойной клик и уходит сюда же — move в ту же папку с новым именем.

Все источники и коллизии проверяются до первого копирования: транзакций в S3 нет, и
частично выполненный перенос хуже отказа. Ошибки:

- `400` — пустой `keys`, пустой или не строковый `destination`, сегмент `..` в пути
  назначения, невалидное `name`, `name` при нескольких ключах, папка перемещается в себя
  или своего потомка, источник не найден;
- `409` — целевой объект или папка уже существует; перезаписи нет.

### Удаление

`DELETE /storage/objects` тело `{ keys }` удаляет ровно перечисленные ключи пачками по 1000
и возвращает `{ deleted }`. Папка удаляется отдельным роутом `DELETE /storage/folder?prefix=`
— он рекурсивно сносит поддерево вместе с маркером. UI при мультивыборе разводит их: файлы
уходят пакетом, каждая выбранная папка — рекурсивным роутом.

## Интерфейс

Реализация страницы — `src/frontend/pages/admin-storage/`. Текущая папка хранится в
query-параметре `prefix` URL, поэтому ссылку на папку можно передать.

- **Командная панель.** `Новая папка`, `Загрузить` | `Переименовать` (ровно один
  выбранный), `Переместить`, `Скачать`, `Удалить` (неактивны без выбора) | поиск,
  `Обновить`, переключатель `Списком`/`Плиткой`.
- **Адресная строка.** Кнопка «вверх» и кликабельные хлебные крошки.
- **Дерево папок** слева: раскрывается лениво при клике, навигация по клику на узел,
  активная папка подсвечена.
- **Список.** Чекбокс, `Имя`, `Размер`, `Изменён`, `Тип`; сортировка кликом по заголовку
  (папки всегда выше файлов); инлайн-переименование и инлайн-создание папки.
- **Мультивыбор.** Клик, `Ctrl`/`Cmd`-клик, `Shift`-клик, чекбоксы, `Ctrl+A`; выбор
  синхронизируется с видимым списком — ушедшие из вида ключи выпадают из него, bulk-операция
  не заденет лишнее.
- **Хоткеи.** `Enter` — открыть, `Esc` — отменить правку или снять выбор, `Delete` —
  удалить выбранное, `F2` — переименовать единственный выбранный.
- **Вид «плитка».** Та же семантика выбора, открытия и контекстного меню, что у списка.
- **Контекстное меню.** Правый клик по строке (`Открыть`, `Скачать`, `Переименовать`,
  `Переместить…`, `Удалить`, `Свойства`) и по пустому месту (`Новая папка`, `Загрузить`,
  `Обновить`).
- **Диалог перемещения.** Навигатор по папкам от корня и кнопка `Переместить сюда`; цель
  «папка в себя или своего потомка» недоступна с подсказкой.
- **Диалог свойств.** Ключ, размер, тип, `etag`, дата изменения; у папки — ключ и тип.
- **Drag&drop.** Строки и плитки перетаскиваются на узлы дерева, строки-папки, крошки и
  кнопку «вверх»; запрещённые цели подсвечиваются, drop переносит без диалога.
- **Статус-бар.** Выбрано / всего / суммарный размер выбранных файлов.

## Предпросмотр

Диалог превью — общая библиотека [`@amplicada/file-viewer`](../../../file-viewer/docs/reference/file-viewer.md):
админка отдаёт ей источник `{ type: 'url', url: view-роут }` и кнопку скачивания, а выбор
рендерера (картинка, видео, аудио, PDF, текст в Monaco, Office docx/xlsx, «открыть в
браузере») — на стороне библиотеки. Тип определяется по расширению ключа: `ListObjectsV2`
`Content-Type` не отдаёт, а HEAD на каждую строку списка — это запрос на файл. Кнопка превью
есть только у типов, которые библиотека умеет показать. Текстовые файлы открываются в режиме
правки (`mode="edit"`) **только когда включён `STORAGE_EDIT_ENABLED`**: сохранение идёт через
`PUT /storage/objects`, список после этого обновляется. По умолчанию — просмотр без правки.

## Ограничения

- Папка отдаётся целиком, пагинации нет.
- Поиск фильтрует только текущую папку на клиенте.
- Файл без расширения превью не получает, даже если это картинка.
- Загрузка — до лимита multipart платформы (100 МБ).
- В свойствах `contentType` и `etag` показываются как `—`: `ListObjectsV2` не возвращает
  `Content-Type`, а отдельного роута метаданных пока нет.
- В SeaweedFS вложенные пустые папки — записи filer, а не объекты листинга: они могут
  пережить удаление или перенос родительской папки.
- Правка — только текст и только существующий объект: `PUT` не создаёт новые ключи, а файлы
  крупнее 5 МБ открываются в режиме правки read-only (потолок редактора библиотеки).
- Правка выключена по умолчанию: без `STORAGE_EDIT_ENABLED=true` роута `PUT` нет, превью
  read-only.
