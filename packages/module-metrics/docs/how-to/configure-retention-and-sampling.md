# Настроить retention и сэмплирование

## Retention

События живут в партициях по месяцам; срок хранения задаётся в днях.

1. Откройте `/admin/apps/metrics` → «Настройки» → «Хранение событий, дней».
2. Сохраните. Значение принимается в диапазоне 1–3650 (`src/backend/services/metrics-service.ts`).

Удаление выполняет задача `metrics.maintenance`: она создаёт партиции на текущий и два
следующих месяца и удаляет партиции, целиком вышедшие за retention (`DETACH ... CONCURRENTLY`
+ `DROP`). Задача регистрируется кодом, но **не активна**, пока в админке (`/admin/tasks`)
не задано расписание — включите её, например, раз в сутки.

Проверить, что партиции созданы:

```sql
select tablename from pg_tables where schemaname = 'metrics' order by tablename;
```

## Сэмплирование

Доли сэмплирования (0–1) применяются трекером на клиенте; в каждом событии сохраняется
фактическая `samplingRate`, поэтому агрегаты можно масштабировать.

- «Доля просмотров» — по умолчанию `1` (все pageview).
- «Доля кликов» — по умолчанию `0.1`; пока используется только будущими UI-событиями.

Установите, например, `0.25` и сохраните. Новые события будут приходить с `sampling.rate = 0.25`.

## Ограничения

- Изменения применяются к новым батчам: уже записанные события не пересчитываются.
- Сырые URL по умолчанию не хранятся; включение `store_raw_urls` расширяет объём и риск PII
  (см. [explanation/pseudonymization.md](../explanation/pseudonymization.md)).
