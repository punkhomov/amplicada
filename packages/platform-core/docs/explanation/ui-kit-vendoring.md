# Почему UI-кит вендорится и как устроен синк

Контекст: `platform-core` владеет UI-китом, который потребляют все модули. Кит собран
из компонентов shadcn/ui: исходники лежат в репозитории, а не приходят из npm-пакета.
Эта страница объясняет, почему так и какие следствия это создаёт для потребителя.

## Компоненты — это исходники, а не зависимость

shadcn/ui распространяется как код: CLI кладёт `.tsx`-файлы в проект, и дальше это
обычный исходник платформы. Это даёт:

- один источник компонентов для всех модулей (deep import `.../frontend/ui/card`);
- отсутствие runtime-зависимости на UI-библиотеку: в бандл попадает только то, что реально
  используется;
- предсказуемые стили: Tailwind сканирует `src/frontend` через `@source "../"`.

Плата — обновления. Upstream не приходит сам: их тянет и нормализует `ui:sync`.

## Почему после скачивания нужен постпроцессор

CLI подставляет в файлы alias-импорты (`@/ui/button`). TypeScript не переписывает пути
при компиляции, поэтому в `dist` попали бы неразрешимые спецификаторы. `ui:sync` заменяет
их на относительные с расширением `.js` — формат, который одинаково понимают `tsc`, Vite
и Node. Заодно снимается `"use client"` (в SPA-сборке директива не нужна) и проверяется,
что в файлах не осталось неразрешённых alias-путей.

## Почему зависимости кита ставит репозиторий, а не CLI

CLI ставит зависимости до записи файлов и падает целиком, если установка не прошла.
Реестр при этом приносит свои пины (`recharts@3.8.0` при пине платформы `3.10.1`)
и свежие версии (`cn`, `@shadcn/react`), которые может не пропустить политика возраста.
Поэтому синк перехватывает установку: файлы обновляются, а состав зависимостей остаётся
решением репозитория. Обновление версий — отдельный осознанный шаг.

## Следствия для потребителя

- Публичная поверхность — deep import'ы `@amplicada/platform-core/frontend/ui/<name>`
  и токен `cn`; имена файлов компонентов стабильны.
- Ломающие изменения Base UI/shadcn приезжают синком и видны в `git diff` — потребитель
  узнаёт о них из typecheck, а не из минорной версии пакета.
- Кастомизировать компонент обёрткой, а не правкой файла: правка исчезнет при синке.

## Что осознанно не поддерживается

- Локальные патчи вендоренных файлов.
- Автообновление `sonner.tsx` (выпал из индекса реестра) и `ext-table.tsx` (собственный).
- Синхронизация без сети: `ui:check` проверяет только нормализацию, не сами компоненты.
