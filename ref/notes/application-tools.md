# Application tools — заметки разработчиков

> Стоп-лист:
> - Не возвращать общую папку профилей и скрытое переключение через env — D-001 (accepted).
> - Не переносить тестовые конфиги к демоприложениям — D-001 (accepted).

## D-001. Композиция без обязательных профилей — accepted (2026-09-15)

**Контекст.** При переходе к discovery остались full/minimal в корне, env-переключатель
с поиском workspace и глобальные входы Turbo. Пользователь попросил убрать эти остатки.
**Решение.** Примеры лежат в `test/fixtures/applications/` и копируются тестом в отдельный
временный проект с фиктивными пакетами. CLI по умолчанию читает dependencies;
`--config` остаётся явной возможностью. Env-переключатель и связанные настройки удалены.
**Почему именно так.** Состав приложения уже выражен его зависимостями; второе описание
не нужно. Проверка генератора не должна зависеть от наличия конкретных модулей в apps.
**Отвергнуто.** Обязательный общий конфиг или автоопределение профиля — добавляют второй
источник состава и мешают сценарию «добавил зависимость, установил, собрал».
**Что изменит решение.** Реальная задача нескольких составов одного приложения,
которую не покрывает явный `--config` или отдельные package.json.
**Грабли.** Обычный build регенерирует imports из dependencies даже после ручного
`--config`. Кэш отдельной задачи с конфигом должен учитывать её inputs. Тесты создают
только фиктивные package.json, ничего не устанавливают. Обязательная политика установки
распространяется на все внешние проверки; её нельзя ослаблять ради прохождения smoke-теста.

`packages/application-tools/src/application.test.ts:169`, `turbo.json`.
