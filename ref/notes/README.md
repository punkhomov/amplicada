# ref/notes/ — заметки разработчиков

Для тех, кто **меняет** пакет. Здесь — почему сделано так, а не иначе: отвергнутые
альтернативы, сознательно отложенное, известные пробелы, грабли. Потребительская
документация живёт рядом с кодом — `packages/<pkg>/docs/`, здесь её не дублировать.

## Зачем

Агент или новый разработчик не должен переоткрывать уже решённое. **Перед изменением пакета**
читай `packages/<pkg>/docs/index.md` (границы и ограничения) и `ref/notes/<pkg>.md`
(решения и пробелы). Если предложение совпадает с `rejected` / `deferred` / `gap` — отвечай
на записанную причину, не открывай решение молча.

## Статусы записей

| Статус | Значение |
|---|---|
| `accepted` | Решение принято и действует. Пересматривается только новой записью с новыми фактами. |
| `rejected` | Рассмотрели и отказались. Повторное предложение обязано ответить на причину отказа. |
| `deferred` | Сознательно отложено. Указывается, что нужно, чтобы вернуться. |
| `gap` | Известный пробел/ограничение. Не баг «не заметили», а записанный факт. |
| `superseded` | Заменено новой записью; поле `superseded_by` обязательно. |

## Формат записи

Записи нумеруются `D-001`, `D-002`, … в порядке появления и не удаляются. Смена решения —
новая запись, старая получает `superseded` и `superseded_by`.

~~~~markdown
## D-001. <Название решения> — accepted (YYYY-MM-DD)

**Контекст.** Что было не так, какой вопрос стоял.
**Решение.** Что сделано, одним-двумя предложениями.
**Почему именно так.** Причины, ограничения, факты.
**Отвергнуто.** Вариант X — почему нет. Вариант Y — почему нет.
**Что изменит решение.** Условие, при котором к вопросу возвращаются.
**Грабли.** Неочевидные следствия, хвосты, дефекты «на будущее».
**Код.** `src/backend/...:NN`
**Связано.** `ref/adr/...`, `ref/plans/...`, `superseded_by: D-NNN`
~~~~

## Стоп-лист

Сверху каждого файла — короткий стоп-лист: самые вероятные повторные предложения, статус
и ссылка на запись. Это первое, что читает агент, поэтому формулировки — в терминах
предложения («не делать X — D-003»), а не решения.

~~~~markdown
# module-x — заметки

> Стоп-лист (D-001…):
> - Не добавлять HTTP-роуты сервису — D-002 (rejected).
> - Не кэшировать список на фронтенде — D-005 (deferred, ждём пагинацию).
~~~~

## Правила

1. **Append-only.** Старые записи не редактируются и не удаляются.
2. **Одна копия.** Рационал живёт здесь; docs ссылаются, но не дублируют.
3. **Код — истина.** Notes описывают текущее состояние; если разошлись с кодом — обнови notes.
4. **ADR выше.** Решение, меняющее контракт платформы или затрагивающее несколько модулей, —
   это ADR (`ref/adr/`), в записи — ссылка на него.
5. **Дата у каждой записи.**
