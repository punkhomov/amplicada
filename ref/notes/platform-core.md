# platform-core — заметки

> Стоп-лист (D-001…D-005):
> - Не вносить локальные правки в `src/frontend/ui/**` — перезапишет синк (D-001).
> - Не заводить alias-импорты (`@/ui/...`) внутри вендоренных файлов — ломает `dist` (D-001).
> - Не возвращать `clsx`/`tailwind-merge` и не описывать `cn` заново локально — D-002.
> - Не позволять `shadcn add` ставить зависимости самому — D-003 (rejected).
> - Не поднимать `minimumReleaseAge` обратно без нового факта — D-004.
> - Не «выравнивать» `recharts` по реестру (3.8.0) — D-005 (rejected).

## D-001. UI-кит вендорится в platform-core и синхронизируется скриптом — accepted (2026-09-17)

**Контекст.** Компоненты shadcn/ui лежат в `packages/platform-core/src/frontend/ui`
(style `base-nova`, Base UI). Добавление и обновление делалось вручную: скачать,
переписать `@/...`-импорты на относительные с `.js`, не забыть про Biome. Требовалась
воспроизводимая автоматизация «скачать все + обновить».

**Решение.** `packages/platform-core/scripts/shadcn-sync.mjs` + скрипты
`ui:sync` / `ui:check`: CLI shadcn скачивает компоненты в platform-core, постпроцессор
переписывает `@/ui|hooks|lib|components` в относительные `.js`, снимает `"use client"`
и падает на неразрешённых alias-путях.

**Почему именно так.** `tsc` не переписывает пути при emit — в `dist` попали бы
неразрешимые спецификаторы. Biome не проверяет `ui/` и `hooks/use-mobile.ts`, поэтому
формат upstream сохраняется. `ui:check` (режим `--check`) даёт офлайн-гейт для будущего CI.

**Отвергнуто.** Runtime-резолв alias-путей (`paths` + бандлер) — ломает Node ESM и `dist`
у потребителей. `package.json#imports` (`#ui/*`) — цель маппинга не может одновременно
указывать и в `src` (для `tsc`), и в `dist` (для потребителей). Отдельный npm-пакет
с китом — теряется «свой исходник», усложняется кастомизация. Ручной копипаст — исходная
боль.

**Что изменит решение.** CLI научится писать относительные импорты сам, появится
`--no-install` или собственный registry с готовыми файлами — скрипт можно будет упростить.

**Грабли.** CLI 4.21 оставляет `"use client"` вопреки `rsc: false` (снимаем сами).
`add --all` тянет deprecated `toast` и свежие `message-scroller`/`questionnaire`.
`sonner` выпал из индекса реестра — файл стареет и обновляется руками. `ext-table.tsx` —
собственный, не из реестра.

**Код.** `packages/platform-core/scripts/shadcn-sync.mjs`, `packages/platform-core/package.json:42`,
`biome.json:17`.

## D-002. `cn` — пакет; локальный `lib/utils.ts` стал ре-экспортом — accepted (2026-09-17)

**Контекст.** Реестр shadcn перешёл на `import { cn } from "cn"` (пакет `cn`, замена
`clsx` + `tailwind-merge`). Старый `lib/utils.ts` собирал `twMerge(clsx(...))`.

**Решение.** Добавлен `cn@0.2.6`; `src/frontend/lib/utils.ts` теперь
`export { cn } from 'cn'`; `clsx` и `tailwind-merge` удалены.

**Почему именно так.** Совпадаем с upstream — синк не конфликтует. Одна реализация
слияния классов в бандле. Публичный API (`cn` из барреля `frontend`) не изменился.

**Отвергнуто.** Кодовод `cn` → `../lib/utils.js` — работал, но расходится с upstream:
каждое обновление реестра снова приносит `"cn"`, поддержка двух реализаций.
`cn@0.3.0` сразу — не проходил политику возраста (см. D-004).

**Что изменит решение.** Выход `cn` из карантина — плановый апгрейд до `0.3.x`
(добавляет `./vite`, `./build`).

**Грабли.** Версия зафиксирована точно; `@shadcn/react` тянет `react >= 19` (у нас 19.2).

**Код.** `packages/platform-core/src/frontend/lib/utils.ts`,
`packages/platform-core/src/frontend/index.ts:65`.

## D-003. Синк не устанавливает зависимости: PATH-шим для CLI — accepted (2026-09-17)

**Контекст.** `shadcn add` сам вызывает `pnpm add` — **до** записи файлов, и при любом
сбое установки завершается целиком. Реестр приносит свои пины (`recharts@3.8.0` против
нашего `3.10.1`) и свежие версии (`cn`, `@shadcn/react`), которые политика возраста
могла не пропустить.

**Решение.** `ui:sync` запускает CLI с временным каталогом в `PATH`, где
`pnpm`/`npm`/`yarn`/`bun`/`deno` — заглушки с `exit 0`. Файлы обновляются, зависимости
репозитория не трогаются; новые пакеты добавляются руками по выводу CLI.

**Почему именно так.** Состав зависимостей — решение репозитория, а не реестра.
Интерцепт делает синк детерминированным и устраняет зависимость от порядка шагов CLI.

**Отвергнуто.** Дать CLI ставить зависимости, затем откатывать `package.json`/`pnpm-lock.yaml`
из git — при сбое установки CLI не доходит до записи файлов, откатывать нечего.
Временное удаление `pnpm-lock.yaml` (чтобы CLI выбрал npm) — хрупко и меняет lockfile-детект.
Патч `node_modules/shadcn` — невоспроизводимо.

**Что изменит решение.** Появление у CLI флага «не ставить зависимости».

**Грабли.** Заглушается только установка; остальные вызовы (`git` для GitHub-реестров)
работают. Если новый компонент требует пакет, `typecheck` упадёт — это и есть сигнал
добавить зависимость.

**Код.** `packages/platform-core/scripts/shadcn-sync.mjs` (`runCli`).

## D-004. `minimumReleaseAge` снижен с 30 до 7 дней — accepted (2026-09-17)

**Контекст.** `cn` (0.2.0–0.3.0, опубликованы 01–12.09.2026) и `@shadcn/react@0.3.1`
не проходили 30-дневный карантин, из-за чего синк кита и новые компоненты были
невозможны. Политика возраста — репо-wide (`pnpm-workspace.yaml`).

**Решение.** `minimumReleaseAge: 10080` (7 дней). Остальные ограничения (`trustPolicy:
no-downgrade`, `ignoreScripts`, `blockExoticSubdeps`) не менялись.

**Почему именно так.** Решение владельца репозитория; 7 дней сохраняет защиту от
свежеопубликованных версий, разблокируя `cn@0.2.x` и `@shadcn/react@0.3.1`.
Не расширяли `minimumReleaseAgeExclude` — исключения по-прежнему не заводятся «ради установки».

**Отвергнуто.** Добавить `cn`/`@shadcn/react` в `minimumReleaseAgeExclude` — запрещено
контекстом проекта. Ждать 30 дней — блокирует работу.

**Что изменит решение.** Инцидент с supply-chain или ужесточение политики на уровне
репозитория. Для отдельного пакета, которому нужна свежая версия, — возврат к обсуждению,
а не молчаливое исключение.

**Грабли.** Правило действует на все пакеты монорепы: обновления теперь проходят быстрее
и это осознанный компромисс.

**Код.** `pnpm-workspace.yaml:6`.

## D-005. `recharts` остаётся `3.10.1`, пин реестра `3.8.0` игнорируется — accepted (2026-09-17)

**Контекст.** Реестр для `chart.tsx` объявляет `recharts@3.8.0`; в platform-core стоит
точный пин `3.10.1` (см. `package.json`).

**Решение.** Версию не откатываем: синк не устанавливает зависимости (D-003), а `chart.tsx`
работает с 3.10.1 (typecheck/build чисты).

**Почему именно так.** Откат — даунгрейд и нарушение `trustPolicy: no-downgrade`;
реестровый пин — «протестировано у них», а не требование совместимости.

**Отвергнуто.** Выровнять по реестру (3.8.0). Поднять до latest без проверки — вне задачи.

**Что изменит решение.** Ломающая несовместимость `chart.tsx` с 3.10.x — тогда точечный
разбор и, при необходимости, откат.

**Код.** `packages/platform-core/package.json` (`recharts`), `src/frontend/ui/chart.tsx`.
