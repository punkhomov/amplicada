# Форматы документов

Скелет каждого типа документа: какие секции и в каком порядке писать.
Структура — рекомендация, не строгий формат.

## Языки

| Тип | Язык |
|-----|------|
| `adr/` | English |
| `plans/` | Russian |
| `guides/` | Russian |

---

## ADR (`adr/NN-name.md`, English)

```
# {Title}

## Status

Accepted (or: Implemented, Superseded by ADR-NN)

## Context

Почему это решение понадобилось. Какая проблема, какие ограничения,
какие требования. Факты без оценки.

## Decision

Что решили — одним-двумя абзацами. Конкретно и недвусмысленно.

## Rationale

Почему именно так. Если были альтернативы — перечислить с pros/cons.

## Consequences

Что изменится. Хорошее и плохое. Честно.

## Implementation Notes (optional)

Кратко как реализовано. Ссылки на код.

## Related (optional)

Ссылки на другие ADR или планы.
```

---

## Plan (`plans/YYYY-MM-DD-name.md`, Russian)

```
# {Название}

## Текущая проблема

Что не так сейчас. Нумерованный список фактов.

## Решение

Что делаем — одним абзацем.

## Архитектура

Схема, ASCII-диаграмма, ключевые компоненты. Код основных интерфейсов,
если нужно.

## Зависимости

Новые пакеты, инфраструктура, env vars. Таблицей.

## Изменения по файлам

Что создаём / меняем. Таблица: файл → действие (+ кратко что).

## Порядок реализации

Шаги, сгруппированные по фазам. С чекбоксами `- [ ]`.
Каждый шаг — конкретное действие, которое можно выполнить
и закоммитить отдельно.

## Проверка

Как тестировать: curl, браузер, ручные тесты.
```

## Guide (`guides/name.md`, Russian)

```
# {Название}

## {Описание — что делает этот guide, для кого}

Основная часть: шаги, паттерны, конвенции.
Каждый шаг сопровождается примером кода.

## {Пример — законченный код, который можно скопировать} (optional)
```

## Notes (`notes/<package>.md`, Russian)

Заметки разработчиков по пакету: решения, отвергнутые альтернативы, отложенное, пробелы.
Полный формат, статусы и шаблон записи — [`notes/README.md`](../notes/README.md).
Диаграмма: docs пакета описывают текущее состояние для потребителя; notes объясняют разработчику,
почему оно такое.

---

## Module docs (`packages/<pkg>/docs/`, Russian)

Потребительская документация пакета: Diátaxis, многостранично — `index.md` + `tutorial.md` +
`how-to/` + `reference/` + `explanation/`. Шаблоны, правила покрытия и VitePress-требования —
скилл `.agents/skills/module-docs/`.
