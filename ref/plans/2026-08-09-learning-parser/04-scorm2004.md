# 04 — SCORM 2004 в глубину

> Сделано 2026-08-09. Что вышло иначе — в
> `scorm2004-sequencing`: детектор использования
> считается по разобранному дереву, а не по сырому XML (поэтому порядок работ внутри фазы другой,
> см. ниже); пустой `<imsss:sequencing/>` даёт объект со всеми `null`, а не `null`;
> `choice-exit-without-choice` заводится при разборе, а не в правилах. Добавилось правило
> `scorm.sequencing-value-unknown`, которого в плане не было.

Сейчас 2004 отличается от 1.2 ровно двумя вещами: `format: 'scorm2004'` и порог, читаемый из
`imsss:minNormalizedMeasure` вместо `adlcp:masteryscore`. Всё, что делает 2004 версией 2004, —
sequencing, objectives, rollup, навигационные ограничения — не разбирается вовсе.

Самая большая фаза плана. В образце на неё приходится 13 547 строк — больше четверти проекта.

## Что появляется

### Редакция

`schemaversion` у 2004 бывает `2004 2nd Edition`, `2004 3rd Edition`, `2004 4th Edition` — и это не
косметика: 4-я редакция добавила `constrainChoiceConsiderations` и `rollupConsiderations`, 3-я —
изменила правила rollup. Потребителю, который однажды напишет рантайм, разница нужна.

Новое поле `edition: '2nd' | '3rd' | '4th' | null`. Источник — текст `schemaversion`; неймспейс для
этого не годится (`adlcp_v1p3` стоит и у 3-й, и у 4-й).

> В образце, кстати, детектор смотрит на `adlcp_v1p3` **и `adlcp_v1p2`** — того же несуществующего
> неймспейса, который мы выкинули в фазе `01`. Повторять не надо.

### Sequencing

`<imsss:sequencing>` на пункте оглавления, плюс `<imsss:sequencingCollection>` в манифесте —
переиспользуемые блоки, на которые пункты ссылаются через `IDRef`. Разрешать ссылки надо при
разборе, иначе потребитель получит наполовину пустой узел и полезет читать манифест сам.

| Элемент | Что задаёт |
|---|---|
| `controlMode` | `choice`, `flow`, `forwardOnly`, `choiceExit` — можно ли прыгать по оглавлению |
| `sequencingRules` | pre/post/exit-условия: «пропустить», «запретить», «выйти из родителя» |
| `rollupRules` | как статус детей складывается в статус родителя |
| `objectives` | primary + вторичные, `minNormalizedMeasure`, `mapInfo` (обмен целями между SCO через глобальные objectives) |
| `limitConditions` | лимиты попыток и времени |
| `randomizationControls` | перемешивание детей, `selectCount` |
| `deliveryControls` | `completionSetByContent`, `objectiveSetByContent` — кто решает, пройдено ли |
| `auxiliaryResources` | вспомогательные ресурсы (глоссарий, справка) |
| `constrainChoiceConsiderations`, `rollupConsiderations` | только 4-я редакция |

`mapInfo` стоит выделить: это единственный механизм, которым два SCO обмениваются результатами, и
без него курс с общей целью «пройден» ведёт себя необъяснимо.

### `adlcp` и `adlnav` на пункте

- `completionThreshold` — доля, при которой считается завершённым (не путать с проходным баллом);
- `timeLimitAction` — уже читается, но у 2004 значения свои (`exit,message` и др.);
- `<adlcp:data><adlcp:map targetID>` — общие «корзины» данных между SCO (`adl.data`);
- `<adlnav:presentation><adlnav:navigationInterface><adlnav:hideLMSUI>` — какие кнопки LMS прятать
  (`continue`, `previous`, `exit`, `abandon`). Прямо влияет на то, что рисует плеер.

### Пользуется ли курс sequencing на самом деле

`SequencingUsageDetector` образца отвечает на этот вопрос: объявлен ли sequencing формально (пустые
`<imsss:sequencing/>`, которые ставят сборщики «на всякий случай») или курс им реально управляет —
есть правила, лимиты, rollup, objectives с картами.

Это **факт, который библиотека сообщает**, а не решение о приёме — так записано в
[`00-overview`](./00-overview.md). Но факт ценный: курс 2004 без реального sequencing отличается от
1.2 переименованными элементами модели данных и больше ничем, то есть проигрывается почти тем же
рантаймом.

Форма: `sequencingUsage: { used: boolean; indicators: string[] }` — не просто флаг, а перечень того,
что именно найдено, иначе `false` невозможно перепроверить.

## Результат перестаёт быть плоским

Это та фаза, ради которой в `00-overview` записано `details`. Общий `PackageMetadata` держать всё
это не должен: `controlMode` не имеет смысла у AICC, а `moveOn` — у SCORM.

```ts
interface Scorm2004Details {
  edition: '2nd' | '3rd' | '4th' | null;
  sequencingUsage: SequencingUsage;
  /** Общие цели, к которым обращаются несколько SCO. Ключ — id цели. */
  globalObjectives: string[];
}
```

Sequencing самого пункта — на пункте: `Activity.sequencing`, поле, которое фаза `01` намеренно не
заводила пустым. Сюда, в `details`, идёт только то, что относится к пакету целиком.

Тип-объединение размечается по `format`, поэтому `metadata.format === 'scorm2004'` сужает
`metadata.details` без приведения типов.

## Правила валидации, которые становятся возможными

| Код | Severity | Что ловит |
|---|---|---|
| `scorm.sequencing-ref-dangling` | warning | `IDRef` на несуществующий блок в `sequencingCollection` |
| `scorm.objective-map-dangling` | warning | `mapInfo` ссылается на глобальную цель, которую никто не объявляет |
| `scorm.rollup-without-children` | warning | Правила rollup на листе — они там ни на что не влияют |
| `scorm.choice-exit-without-choice` | warning | `choiceExit` при выключенном `choice` |

## Порядок работ внутри фазы

Дробить стоит, иначе один коммит на две тысячи строк:

1. `edition` + `sequencingUsage` — самостоятельная ценность, ничего не ломает;
2. `details` как тип и его размётка по `format` — здесь ломается форма результата;
3. `Activity.sequencing`: controlMode, objectives, limitConditions — то, что нужно плееру раньше
   всего;
4. sequencingRules и rollupRules — самое объёмное;
5. `adlnav` и `adlcp:data`;
6. правила валидации.

> По факту порядок вышел другой: `sequencingUsage` уехал после разбора, потому что считается по
> разобранному дереву. Признаки по сырым узлам манифеста пришлось бы описать дважды — сначала по
> XML, потом по модели, — и они разъехались бы на первом же дополнении. Шаг 1 остался
> самостоятельным только в части `edition`.

## Чем проверяем

Фикстуры от ADL (Golf Sample из Content Packaging и Sequencing) — форма, на которой sequencing
объявлен по-настоящему. Плюс:

- пустой `<imsss:sequencing/>` даёт `used: false` — иначе детектор бесполезен;
- ссылка на `sequencingCollection` разрешается, и результат неотличим от объявления по месту;
- редакция читается из всех трёх написаний `schemaversion`;
- 2004-пакет **без** sequencing разбирается так же, как 1.2, — то есть фаза ничего не сломала.

## Оценка

Самая большая: 700–1000 строк разбора плюс тесты. Дробить по списку выше.

## Чего не делаем

- **Движок sequencing.** Разобрать правила и **исполнить** их — разные задачи; вторая это
  полноценный автомат состояний с деревом активностей, и ей место в рантайме, которого у библиотеки
  нет и не будет.
- **Валидацию по XSD** — решено в `00-overview`.
