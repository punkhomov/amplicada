# 05 — пререквизиты

> Сделано 2026-08-09. Что вышло иначе — в `prerequisites`:
> `common.prerequisite-unparsable` разделён надвое (законная конструкция полного скрипта отличается
> от мусора), добавились `scorm.prerequisites-type-unknown` и `aicc.prerequisites-unreadable`, а
> запись `.pre` рёбрами (`source`/`target`) намеренно **не** читается — направление из имён колонок
> не следует. Находки о неразобранном заводятся при разборе, а не в правилах.

`adlcp:prerequisites` читается как строка и на этом всё. Строка эта — выражение на своём языке, и
без разбора она бесполезна: «не пускать в главу 3, пока не пройдена 2» остаётся текстом в поле.

## Язык

SCORM 1.2 заимствовал его у AICC (`type="aicc_script"`). Грамматика — рекурсивный спуск, сверено с
образцом:

```
expression → term ('|' term)*
term       → factor ('&' factor)*
factor     → '~'? atom
atom       → IDENTIFIER | '(' expression ')'
IDENTIFIER → [A-Za-z0-9_-]+
```

Приоритеты по убыванию: `~` (НЕ, унарный), `&` (И), `|` (ИЛИ). Идентификаторы — это `identifier`
пунктов оглавления, то есть ровно то, что фаза `01` уже кладёт в `Activity.identifier`. Без дерева
эту фазу делать было бы не к чему привязывать — отсюда и порядок.

Полный AICC-скрипт богаче: `*` (множества), `{n}` («любые n из»), сравнения по баллу. Образец
поддерживает подмножество выше. **Начинаем с того же подмножества**, но парсер пишем так, чтобы
неизвестная конструкция давала находку, а не молчаливое «условие не выполнено» — второе опаснее,
потому что запирает учащегося в курсе без объяснений.

## Форма

Разбор в дерево, а не в замыкание: выражение надо уметь показать в интерфейсе («чтобы открыть,
пройдите: Введение и Практика»), а не только вычислить.

```ts
export type Prerequisite =
  | { kind: 'item'; identifier: string }
  | { kind: 'not'; operand: Prerequisite }
  | { kind: 'and'; operands: Prerequisite[] }
  | { kind: 'or'; operands: Prerequisite[] };

export function parsePrerequisites(source: string): Prerequisite | null;
/** Вычисление по множеству пройденных пунктов. Чистая функция — никакого состояния попытки. */
export function evaluatePrerequisites(expression: Prerequisite, completed: ReadonlySet<string>): boolean;
```

`Activity.prerequisites: Prerequisite | null` — новое поле узла дерева.

**Вычисление отдаём наружу как функцию, но не вызываем сами.** Что считать «пройденным» — вопрос
рантайма (`completed`? `passed`? `completed || passed`?), и решать его должен потребитель. Библиотека
даёт дерево и способ его посчитать.

## AICC

Тот же язык, но живёт в трёх местах: колонка в `.au`, файл `.pre`, поле `prerequisites` в строке
`.cst` (в структуре оно есть — фаза `01` его не читала, потому что собирала только рёбра).

Идентификаторы там — `system_id` единиц, то есть снова `Activity.identifier`. Разбор общий,
источники разные: `formats/aicc/prerequisites.ts` только достаёт строки и зовёт общий парсер.

Общее место — `model/prerequisite.ts`: тип и парсер не привязаны к формату, потому что язык один.

## Правила валидации

| Код | Severity | Что ловит |
|---|---|---|
| `common.prerequisite-unparsable` | warning | Выражение не разбирается. Игнорировать нельзя: непонятое условие — это либо вечно закрытая глава, либо вечно открытая |
| `common.prerequisite-unknown-item` | warning | Ссылка на `identifier`, которого нет в дереве |
| `common.prerequisite-cycle` | warning | A требует B, B требует A — курс, в который нельзя войти |

> Кодов вышло шесть. `common.prerequisite-unsupported` отделён от `unparsable`: `a*b` — законный
> AICC-скрипт, до которого мы не дошли, а `a & & b` — мусор в пакете, и чинить их разным людям.
> `scorm.prerequisites-type-unknown` — условие объявлено на чужом языке. `aicc.prerequisites-unreadable`
> — в `.pre` нет колонки с выражением.

Цикл стоит отдельного упоминания: его легко получить копипастой пунктов в редакторе курса, и без
проверки он проявится только у учащегося, который упрётся в запертые главы без причины.

## Чем проверяем

- каждый оператор и приоритеты: `a&b|c` — это `(a&b)|c`, а не `a&(b|c)`;
- скобки меняют приоритет;
- `~a&b` — отрицание связывает только `a`;
- пробелы внутри выражения игнорируются (в живых пакетах их ставят как попало);
- пустая строка и мусор → `null` плюс находка, а не исключение;
- неизвестная конструкция (`a*b`, `{2}`) → находка с текстом, а не тихое `false`;
- вычисление: множество пройденных даёт ожидаемый ответ на всех формах выше;
- цикл ловится и не уводит проверку в бесконечную рекурсию.

## Оценка

200–250 строк: токенизатор, рекурсивный спуск, вычислитель, три правила. Плюс подключение к двум
форматам.

## Чего не делаем

- **Полный AICC-скрипт** (`*`, `{n}`, сравнения по баллу) — пока не встретится в реальных пакетах.
  Находка о неизвестной конструкции для того и нужна, чтобы это стало видно.
- **Применение пререквизитов** — это рантайм. Библиотека отдаёт дерево и вычислитель.
- **Пререквизиты SCORM 2004** — их там нет: эту роль играет sequencing, фаза `04`.
