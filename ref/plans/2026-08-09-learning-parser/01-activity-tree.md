# 01 — дерево оглавления

Разбор находит все запускаемые пункты и **оставляет первый**, отдавая наружу счётчик
`launchableCount: number`. Для решения «принять или отказать» этого хватает, для проигрывания нет.

## Зачем

**Структура — то, на что вешается всё остальное.** Sequencing SCORM 2004 объявляется на пункте
дерева, пререквизиты ссылаются на пункты по идентификатору, objectives принадлежат пункту. Пока
дерева нет, фазы `04` и `05` некуда класть; сделать их раньше — значит потом переписать.

Для потребителя это выглядит так: курс из пяти SCO — **пять отдельных попыток** со своими
`lesson_status`, `score`, `session_time`. Без дерева нашей платформе:

- нечего показать в оглавлении и нечем переключать SCO ([`06`](../2026-08-08-module-learning/06-frontend-catalog-player.md));
- не к чему привязать попытку, кроме пакета целиком, — то есть курс либо пройден, либо нет, без
  прогресса ([`05`](../2026-08-08-module-learning/05-scorm-runtime.md));
- нечем заполнить половину модели данных SCORM 1.2 (см. ниже — это не абстрактная потеря, а
  конкретные элементы `cmi.*`).

## Что в манифесте лежит на пункте, а не на пакете

Разбор сейчас берёт с первого пункта только `masteryscore`. На `<item>` SCORM 1.2 объявлено ещё
несколько вещей, и каждая напрямую отображается в модель данных рантайма:

| В манифесте | В рантайме | Что будет без него |
|---|---|---|
| `adlcp:datafromlms` | `cmi.launch_data` | Курсы, передающие себе конфигурацию через манифест, стартуют в дефолтном режиме |
| `adlcp:masteryscore` | `cmi.student_data.mastery_score` | Порог берётся с первого SCO для всех |
| `adlcp:maxtimeallowed` | `cmi.student_data.max_time_allowed` | Ограничение времени не доезжает до SCO |
| `adlcp:timelimitaction` | `cmi.student_data.time_limit_action` | То же |
| `adlcp:prerequisites` | — (фаза `05`) | Порядок прохождения не соблюдается |
| `@isvisible="false"` | — (оглавление) | Служебные пункты видны учащемуся |
| `@parameters` | хвост URL запуска | Уже учитывается, но только для первого пункта |

`isvisible="false"` — это **скрыть из оглавления, не выкинуть из дерева**: пункт остаётся частью
структуры и на него можно попасть переходом.

## Модель

Новый файл `model/activity.ts` — общий для всех форматов, как `metadata.ts`:

```ts
export interface Activity {
  /** Идентификатор из пакета. Уникален внутри пакета — на него ссылаются пререквизиты и попытки. */
  identifier: string;
  title: string | null;
  /** Куда переходить. `null` у контейнеров — глав и модулей, которые сами не запускаются. */
  launch: LaunchTarget | null;
  /** Идентификатор ресурса, из которого взята точка входа. Нужен правилам валидации. */
  resourceId: string | null;
  /** Скрытый пункт остаётся в дереве, но не показывается в оглавлении. */
  visible: boolean;
  masteryScore: number | null;
  /** Секунды. `maxtimeallowed` в манифесте — длительность вида `HH:MM:SS(.S)`. */
  maxTimeSeconds: number | null;
  timeLimitAction: string | null;
  launchData: string | null;
  children: Activity[];
}
```

`PackageMetadata` меняется так: `launchableCount: number` уходит, появляется
`activities: Activity[]` (корни дерева). Число запускаемых считается обходом там, где нужно;
хранить его отдельным полем, когда есть дерево, — приглашение к рассинхрону.

`entryPoint`/`entryUrl` **остаются**: точка входа по умолчанию нужна и приёму, и плееру, который
открывает курс без выбора. Это первый запускаемый пункт обхода в глубину — ровно то, что
вычисляется сейчас.

## По форматам

| Формат | Откуда дерево |
|---|---|
| SCORM 1.2 / 2004 | `<organization>` по умолчанию, вложенные `<item>`; лист — тот, у кого `identifierref` ведёт на ресурс с `href` |
| cmi5 | `<block>` → узлы, `<au>` → листья; и то и другое уже обходится в `collectUnits`, надо перестать уплощать |
| xAPI | `<activity>` плоским списком: вложенности в формате нет |
| AICC | `.cst` — структура блоков (сейчас не читается вовсе), `.au` — единицы, `.des` — названия |

**Разрешение `href` придётся переделать.** Сейчас `xml:base` складывается по цепочке только для
ресурса точки входа. У каждого пункта дерева свой ресурс со своим `xml:base`, поэтому склейка базы
переезжает внутрь обхода, а не остаётся частным случаем.

## Где это потом хранится — не в этой фазе

Вопрос бекенда платформы, **отложен** (решение 2026-08-09): разбирать манифест на каждое открытие
курса или разложить дерево в таблицу при приёме. Решается в
[`05-scorm-runtime`](../2026-08-08-module-learning/05-scorm-runtime.md), когда определится форма
попытки — там же выбирается, что считать единицей прохождения.

Библиотека отдаёт дерево и от этого выбора не зависит. Здесь он записан только чтобы не всплыл как
неожиданность: если попытка будет ссылаться на пункт по FK, а не строкой-путём, у пунктов должен
быть стабильный идентификатор — `Activity.identifier` из манифеста им и является.

## Чем проверяем

Фикстуры в тестах пакета, без БД и S3 — как всё остальное там:

- вложенность три уровня, точка входа на третьем;
- контейнер без `identifierref` — узел, а не лист, и не «пункт без href» в отказ;
- `isvisible="false"` — в дереве есть, во «что показать» нет;
- две организации с `organizations/@default` — дерево из указанной, не из первой;
- разные `xml:base` у соседних ресурсов — каждый пункт резолвится своей базой;
- `identifierref` в никуда — пункт остаётся узлом, разбор не падает;
- дубль `identifier` между пунктами — фиксируем поведение (первый выигрывает, как уже сделано для
  ресурсов);
- cmi5 с вложенными `<block>` — дерево, а не плоский список;
- AICC с `.cst` — блоки, и отдельно случай без `.cst` (плоский список единиц).

Плюс проверка, что `entryPoint` не поехал: то же значение, что до фазы, на всех существующих
фикстурах.

## Оценка

Порядка 250–350 строк разбора и модели плюс тесты. Основная работа не в обходе — он уже написан, —
а в переносе резолва `xml:base` внутрь обхода и в четырёх форматах, каждый со своей формой дерева.

## Что не делаем в этой фазе

- **Sequencing SCORM 2004** (`<imsss:sequencing>` на пункте) — фаза `04`. Поле под него в `Activity`
  сейчас не заводим: пустое поле «на будущее» хуже отсутствующего. Место, куда оно встанет, известно —
  узел дерева, — и это единственное, что от этой фазы требуется.
- **Пререквизиты** (`adlcp:prerequisites` уже читается как строка, но не разбирается) — фаза `05`.
- **Сохранение дерева в БД** — сторона платформы, см. выше.
