# План: i18n — интернационализация

## Текущая проблема

- Весь UI-текст хардкодом на русском во всех компонентах
- Нет инфраструктуры для переключения языка
- Backend возвращает русские строки ошибок вместо error codes
- Нет механизма для модулей поставлять свои переводы
- При попытке добавить второй язык придётся менять каждый компонент вручную

## Решение

Внедрить `i18next` + `react-i18next`. Core владеет i18n-инфраструктурой, каждый модуль поставляет свои переводы. Инициализация прозрачна — `bootstrapFrontend` сам собирает locale resources из модулей.

**Статус (2026-07-31):** Фазы 1, 2, 3 и 4 реализованы полностью для фронтенда. Все строки `module-auth-password`, `module-admin` (5 pages + 11 widgets + `admin-layout.tsx` + `lib/cron-schedule.ts`) и `apps/web/routes/home.tsx` переведены на `t()`. Backend (Фаза 5) не начат — вне текущего скоупа (только фронтенд).

## Архитектура

```
packages/platform-core/          ← владелец i18n
  src/
    frontend/
      lib/i18n.ts                ← createI18n(), re-export useTranslation/Trans из react-i18next
      types/i18next.d.ts         ← CustomTypeOptions для core namespace
      locales/ru.json            ← namespace "core": базовые строки
      locales/index.ts           ← export { coreLocales }
      app.tsx                    ← bootstrapFrontend собирает locales из модулей
    backend/
      lib/i18n.ts                ← createI18n() для Fastify
      locales/ru.json            ← namespace "core": ошибки, бизнес-логика
      locales/index.ts           ← export { coreLocales }

packages/module-admin/
  src/frontend/locales/ru.json   ← namespace "admin", один файл на весь модуль (не per-slice)
  src/frontend/locales/index.ts  ← export { adminLocales }
  src/frontend/setup.tsx         ← adminFrontendModule — сюда добавляется поле locales

packages/module-auth-password/
  src/frontend/locales/ru.json   ← namespace "auth"
  src/frontend/locales/index.ts  ← export { authLocales }
  src/frontend/setup.tsx         ← authPasswordFrontendModule — сюда добавляется поле locales
```

**Примечание про FSD (ADR-003):** модули уже мигрированы на Feature-Sliced Design — `pages/<name>/ui/<name>.tsx`, `widgets/<name>/ui/<name>.tsx`, `features/<name>/ui/<name>.tsx`, каждый со своим `index.ts` (barrel). Точка регистрации модуля (`FrontendModule` с `setup()`) — это `setup.tsx`, а `index.ts`/`index.tsx` — публичный barrel пакета. Locale-файлы (`locales/ru.json`) не относятся к FSD-слоям — это module-wide ресурс, лежит в корне `src/frontend/`, как `tailwind.css`.

### Ключевые интерфейсы

#### core/frontend — createI18n + html[lang]

```ts
// packages/platform-core/src/frontend/lib/i18n.ts
import i18n from 'i18next';
import { initReactI18next, useTranslation, Trans } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

export type LocaleResources = Record<string, Record<string, Record<string, string>>>;

export function createI18n(resources: LocaleResources) {
  i18n
    .use(LanguageDetector)
    .use(initReactI18next)
    .init({
      fallbackLng: 'ru',
      resources,
      ns: Object.keys(resources[Object.keys(resources)[0]] ?? {}),
      defaultNS: 'core',
      interpolation: { escapeValue: false },
      detection: {
        order: ['localStorage', 'navigator', 'htmlTag'],
        caches: ['localStorage'],
        lookupLocalStorage: 'i18n_lng',
      },
    });

  document.documentElement.lang = i18n.language;
  i18n.on('languageChanged', lng => {
    document.documentElement.lang = lng;
  });

  return i18n;
}

export { i18n, useTranslation, Trans };
```

#### TypeScript — автокомплит для core namespace

```ts
// packages/platform-core/src/frontend/types/i18next.d.ts
import 'i18next';
import ru from '../locales/ru.json';

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'core';
    resources: {
      core: typeof ru;
    };
  }
}
```

**Важно:** TypeScript не умеет мержить `resources` из нескольких module augmentation'ов (последний победит). Поэтому автокомплит работает только для `core` namespace на глобальном уровне. В модулях для автокомплита используем `keyof typeof`:

```tsx
import type ru from '../locales/ru.json';
type AdminKeys = keyof typeof ru;

const { t } = useTranslation('admin');
// t(key) — без глобального автокомплита, но можно:
t('admin_title' satisfies AdminKeys);
```

Либо, если не нужен строгий автокомплит — просто `t('key')` возвращает `string`.

#### FrontendModule — новое поле locales

```ts
// packages/platform-core/src/contracts/frontend/module.ts
export interface FrontendModule {
  id: string;
  name: string;
  version: string;
  dependencies?: string[];
  locales?: {
    frontend?: Record<string, Record<string, string>>; // { "ru": { "key": "value" } }
  };
  setup(context: FrontendSetupContext): void | Promise<void>;
  start?(): void | Promise<void>;
  stop?(): void | Promise<void>;
}
```

#### bootstrapFrontend — сбор locales

```ts
// packages/platform-core/src/frontend/app.tsx
import { coreLocales } from './locales/index.js';
import { createI18n } from './lib/i18n.js';

export async function bootstrapFrontend(modules: FrontendModule[], context: FrontendSetupContext) {
  // === Phase 1: сбор и инициализация i18n ===
  const resources: Record<string, Record<string, Record<string, string>>> = {};

  for (const mod of modules) {
    if (mod.locales?.frontend) {
      for (const [lang, strings] of Object.entries(mod.locales.frontend)) {
        (resources[lang] ??= {})[mod.id] = strings;
      }
    }
  }

  // core locales добавляются отдельно
  (resources.ru ??= {}).core = coreLocales.ru;

  createI18n(resources);

  // === Phase 2: регистрация модулей (как сейчас) ===
  for (const mod of modules) {
    context.modules.register({ id: mod.id, name: mod.name, version: mod.version });
    await mod.setup(context);
  }
  for (const mod of modules) {
    await mod.start?.();
  }
}
```

**Почему i18n до setup:** модули в `setup()` могут использовать `t()` — если у них нет перевода, сработает fallback на язык по умолчанию.

### Namespace convention

Namespace = `mod.id` из `moduleManifest` (без отдельного маппинга — `bootstrapFrontend` использует `mod.id` как ключ ресурса напрямую, см. `app.tsx`). Реальные id модулей:

| Namespace | Владелец | Примеры ключей |
|-----------|-----------|----------------|
| `core` | platform-core | `loading`, `common_save`, `common_cancel`, `common_delete`, `common_confirm` |
| `admin` | module-admin (`id: 'admin'`) | `admin_title`, `admin_tab_data`, `admin_toggle_theme`, `admin_logout` |
| `auth-password` | module-auth-password (`id: 'auth-password'`, **не `auth`**) | `login_title`, `login_submit`, `login_error_invalid`, `change_password_*` |

Использование в компонентах:

```tsx
// Внутри module-admin — явный namespace
const { t } = useTranslation('admin');
t('admin_title');

// Доступ к общим строкам core
t('core:common_save');

// В хуках/утилитах вне компонента — через i18n instance
import { i18n } from '@amplicada/platform-core/frontend';
i18n.t('core:loading');
```

**Оговорка:** `i18n.t(...)` вне компонента (например, в `setup()` при регистрации toolbar action с `label: i18n.t(...)`) вычисляется один раз при регистрации и не переподписывается на смену языка — переключение `LanguageSwitcher` его не обновит без явного повторного вызова `setup()`. Для строк, которые должны быть реактивными, использовать `useTranslation()` внутри компонента, а не заранее вычисленные конфиг-объекты.

### Ключи — формат

Плоские с префиксами для группировки. Без вложенности:

```json
{
  "login_title": "Вход в систему",
  "login_submit": "Войти",
  "login_error_invalid": "Неверный логин или пароль",
  "login_error_server": "Ошибка сервера",
  "loading": "Загрузка...",
  "not_found": "Не найдено",
  "common_save": "Сохранить",
  "common_cancel": "Отмена",
  "common_delete": "Удалить",
  "common_confirm": "Подтвердить"
}
```

Плюсы: tree-shaking при future code-splitting, простой поиск по ключу.

## Зависимости

| Пакет | Версия | Установить в |
|-------|--------|-------------|
| `i18next` | latest | `platform-core`, `apps/api` |
| `react-i18next` | latest | `platform-core` |
| `i18next-browser-languagedetector` | latest | `platform-core` |

`i18next` — не Next.js, чистая i18n-библиотека без привязки к фреймворку; `react-i18next` — обвязка под обычный React (хуки, `<Trans>`), совместима с нашим стеком. Типы поставляются вместе с `i18next` с v21+ — отдельный `@types/i18next` не нужен (это устаревший stub-пакет).

npm-скрипты:

| Где | Команда |
|-----|---------|
| `platform-core` | `pnpm add i18next react-i18next i18next-browser-languagedetector` |
| `apps/api` | `pnpm add i18next` |
