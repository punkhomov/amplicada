# 📚 Суммаризация: Встраивание движков курсов в приложение

## 🎯 Общая концепция

**Архитектура "Headless LMS"** — собственный фронтенд + поддержка стандартов e-learning (SCORM/xAPI/cmi5) + хранение контента в S3.

---

## 🏗️ Архитектура системы

```
┌─────────────────────────────────────────────────────────┐
│                    FRONTEND (Плеер)                      │
│  ┌──────────────┬──────────────┬─────────────────────┐  │
│  │ scorm-again  │ xapi-wrapper │ Content Renderer    │  │
│  │ (iframe API) │ (statements) │ (HTML/Video/Quiz)   │  │
│  └──────────────┴──────────────┴─────────────────────┘  │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│                    BACKEND (Менеджер)                    │
│  • Загрузка ZIP-пакетов                                 │
│  • Парсинг imsmanifest.xml                              │
│  • Хранение метаданных в БД                             │
│  • Управление правами доступа                           │
│  • Генерация signed URLs / прокси                       │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│                 S3 + CloudFront (Склад)                  │
│  • Статические файлы курсов                             │
│  • CDN для быстрой раздачи                              │
│  • Pre-signed URLs для приватного доступа               │
└─────────────────────────────────────────────────────────┘
```

## 📦 Технологический стек

### Фронтенд (JS/TS библиотеки)

| Задача | Библиотека | Назначение |
|--------|-----------|------------|
| **SCORM** | `scorm-again` | Эмуляция `window.API`, поддержка SCORM 1.2/2004/AICC/cmi5 |
| **xAPI** | `@rusticisoftware/xapi-wrapper` | Формирование и отправка statements в LRS |
| **cmi5** | `cmi5-js` | Launch sequence и handshake с LMS |
| **Альтернатива SCORM** | `@pqina/scorm` | Легковесная обвязка |

### Бэкенд (Node.js)

| Задача | Библиотека |
|--------|-----------|
| Парсинг манифеста | `scorm-manifest-parser` |
| Распаковка ZIP | `unzipper` |
| XML-парсинг | `fast-xml-parser` |
| Работа с S3 | `@aws-sdk/client-s3` |

### Инфраструктура
- **Хранилище:** AWS S3 / Cloudflare R2 / Wasabi / MinIO
- **CDN:** CloudFront / Cloudflare
- **LRS (опционально):** Learning Locker (self-hosted), Watershed (cloud)

## 📐 Стандарты e-learning

### SCORM
- **Формат:** ZIP-архив + `imsmanifest.xml`
- **Механизм:** iframe + `window.API` объект
- **Когда использовать:** Совместимость со старым контентом (Articulate, Captivate)
- **Ключевые методы:** `LMSInitialize`, `LMSGetValue`, `LMSSetValue`, `LMSCommit`

### xAPI (Tin Can)
- **Формат:** JSON statements
- **Механизм:** Прямые HTTP-запросы в LRS
- **Когда использовать:** Новый контент, гибкая аналитика, мобильные приложения
- **Структура:** `actor` + `verb` + `object` + `result`

### cmi5
- **Формат:** Надстройка над xAPI
- **Механизм:** Launch URL + token exchange
- **Когда использовать:** Строгая спецификация, enterprise-решения

## 🔑 Ключевые технические детали

### 1. Распределение ответственности
- **Фронтенд:** рендеринг, взаимодействие со стандартами, трекинг прогресса
- **Бэкенд:** парсинг пакетов, метаданные, авторизация, раздача URL
- **S3:** хранение и раздача статических файлов

### 2. Критичные настройки S3

**CORS** (обязательно для iframe):
```json
{
  "AllowedOrigins": ["https://yourapp.com"],
  "AllowedMethods": ["GET", "HEAD"],
  "AllowedHeaders": ["*"]
}
```

**MIME-типы** (иначе JS/HTML не заработают):
- `.html` → `text/html`
- `.js` → `application/javascript`
- `.css` → `text/css`
- `.xml` → `application/xml`

**Static Website Hosting** — включить для работы `index.html`.

### 3. Доступ к приватным курсам
- **Pre-signed URLs** — для отдельных файлов
- **CloudFront + Cookie auth** — для пакетов с относительными путями (рекомендуется)
- **Прокси через бэкенд** — проще, но медленнее

### 4. Безопасность
- SCORM-пакеты содержат произвольный JS → запускать **только в sandboxed iframe**
- Валидация ZIP перед распаковкой
- Ограничение размеров и типов файлов

## 💡 Рекомендации по внедрению

### Приоритет стандартов
1. **Начать с xAPI** — современнее, гибче, проще в интеграции
2. **Добавить SCORM** — если нужна совместимость с готовыми курсами
3. **cmi5** — только если требуется enterprise-совместимость

### Пошаговый план
1. Настроить S3 + CloudFront с правильными CORS/MIME
2. Реализовать бэкенд-загрузчик ZIP с парсингом манифеста
3. Создать фронтенд-плеер на базе `scorm-again`
4. Подключить xAPI-трекинг через `@rusticisoftware/xapi-wrapper`
5. Реализовать сохранение прогресса в свою БД
6. Добавить систему прав доступа (signed URLs / CloudFront auth)

### Альтернативы для экономии
- **Cloudflare R2** вместо S3 — нет платы за исходящий трафик
- **Wasabi** — в 5 раз дешевле S3, S3-совместимый API
- **MinIO** — если нужен self-hosted вариант

---

## ⚠️ Подводные камни

1. **MIME-типы в S3** — самая частая причина "не работает SCORM"
2. **CORS для iframe** — без него контент не загрузится
3. **Относительные пути** в SCORM-пакетах ломают pre-signed URLs → нужен CloudFront
4. **Размер пакетов** — видео-курсы могут весить гигабайты, продумайте стратегию загрузки
5. **Кросс-доменная коммуникация** между iframe и родителем требует правильной настройки `postMessage`

---

**Итоговая формула:** Ваш бэкенд = умный склад, фронтенд = умный плеер, S3 = бесконечный склад. Библиотеки `scorm-again` + `xapi-wrapper` закрывают 95% работы со стандартами.
