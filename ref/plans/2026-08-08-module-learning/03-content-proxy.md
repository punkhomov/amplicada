# 03 — раздача контента и изоляция

> **Сделано 2026-08-11** вместе с `05` — по отдельности они не проверяемы.
> Итоги, расхождения и известные ограничения требуют проверки по коду.
> Не сделано из описанного здесь: проверка назначения на точке входа (назначений никто не создаёт —
> UI нет), `redact` токена в access-логе, `Content-Disposition: attachment` для типов вне инлайн-whitelist.
> Добавилось сверх плана: `Access-Control-Allow-Origin` (запросы курса уходят с `Origin: null`) и
> побайтовая склейка через `latin1` — курс в windows-1251, прочитанный как UTF-8, ломается.

Отдать файлы пакета в браузер так, чтобы чужой JS внутри курса не получил прав пользователя.
Модель изоляции принята в [00-overview](./00-overview.md#изоляция-контента) — здесь реализация.
Зависит от `01` (стриминг) и `02` (инвентарь).

## Роут

```
GET /api/learning/content/:token/:packageId/*
```

Токен — **в префиксе пути, а не в query**: относительные ссылки внутри пакета (`./js/main.js`,
`../media/intro.mp4`) резолвятся браузером относительно текущего URL и тащат префикс сами. Ни одной
строчки HTML переписывать не нужно — а переписывание чужой разметки регулярками и было бы главным
источником «у нас курс не открывается».

**Регистрируется отдельным `app.register`-скоупом, без сессионного `preHandler`.** Это принципиально:
у контента нет и не может быть сессии — из sandbox-документа с opaque origin cookie не уходит
(`SameSite=Lax` режет запросы с `Origin: null`). Единственный кредитив — токен.

## Токен

HMAC-SHA256 над компактным payload, `base64url`:

```
payload = { u: userId, p: packageId, a: attemptId, e: expiresAt }
token   = base64url(payload) + '.' + base64url(hmac(secret, payload))
```

- Секрет — `LEARNING_CONTENT_SECRET`; если не задан, выводится из `SESSION_SECRET` через HKDF, чтобы
  не подписывать две разные вещи одним ключом.
- Выдаётся при открытии плеера (`06`), TTL порядка длительности сессии просмотра.
- **Принимается только роутами контента и рантайма** (`05`). Ни один обычный API-роут его не знает —
  иначе утёкшая ссылка превращалась бы в сессию.
- Проверка подписи дешёвая (без БД), но **на entry-точку дополнительно проверяется назначение в БД** —
  чтобы отзыв доступа не ждал истечения токена. Подресурсы проверку в БД не повторяют: это сотни
  запросов на один курс.

**Токен в URL попадает в access-логи Fastify** — сегмент `:token` редактируется в логгере
(`redact`), иначе лог становится хранилищем действующих ключей доступа.

## Резолв пути — по инвентарю, не конкатенацией

```ts
const rel = normalizeRelativePath(request.params['*']);   // без ../, без ведущего /
const file = await db.select().from(packageFiles)
  .where(and(eq(packageFiles.packageId, packageId), eq(packageFiles.path, rel))).limit(1);
if (!file) return reply.code(404).send();
const object = await storage.getObjectStream(`learning/${packageId}/${rel}`, { range: request.headers.range });
```

Ключ S3 собирается **после** того, как путь найден строкой в `package_files`. Traversal и «курс
читает соседние объекты бакета» закрываются тем, что несуществующая в инвентаре строка — это 404,
а не попытка чтения. `Content-Type` берётся из той же строки.

## Заголовки

| Заголовок | Значение | Зачем |
|---|---|---|
| `Content-Security-Policy` | `sandbox allow-scripts allow-modals; default-src <origin>; connect-src <origin>; frame-ancestors <origin>` | Основной механизм изоляции: применяется к документу **как бы его ни открыли**, в отличие от атрибута на iframe. `allow-forms`/`allow-popups` добавлять только когда реальный пакет сломается |
| `X-Content-Type-Options` | `nosniff` | `.txt` в пакете не должен отсниффиться как HTML |
| `Referrer-Policy` | `no-referrer` | Иначе токен уедет в `Referer` по внешней ссылке из курса |
| `Cache-Control` | `private, max-age=31536000, immutable` | Файлы пакета иммутабельны: префикс содержит `packageId` |
| `Accept-Ranges` | `bytes` | |
| `Content-Disposition` | `attachment` для типов вне whitelist инлайна | Неизвестное не рендерим как документ |

**Никогда `allow-same-origin` вместе с `allow-scripts`** — пара самоотменяющаяся, документ снимает
с себя песочницу.

**Кэш промахивается между сессиями**, потому что токен меняет URL. Это осознанная цена схемы (см.
«Открытые вопросы» в overview): внутри одной сессии кэш работает, а это и есть основная нагрузка —
сотни мелких файлов на старте курса.

## Range и коды ответа

`getObjectStream` уже возвращает `contentRange`, если S3 ответил частично:

- есть `contentRange` → `206` + `Content-Range` + `Content-Length` (длина куска);
- нет → `200` + `Content-Length`;
- диапазон вне размера → сервис бросает ошибку со `statusCode: 416`, обработчик модуля отдаёт её как есть.

## Инжект рантайма

Только для `entry_point` и только при `kind='scorm12'`: перед отдачей HTML в него вставляется
`<script>` с рантаймом и стартовым состоянием. Детали — в [05](./05-scorm-runtime.md); здесь важно
лишь, что **инжектится ровно одна точка входа**, остальные файлы отдаются байт-в-байт. Вставка —
перед `</head>` (или в начало `<body>`, если `</head>` нет), поиск нечувствителен к регистру.

Только эта одна страница отдаётся без `Cache-Control: immutable` — в неё вшит токен и стартовый `cmi`.

## Проверка

1. Открыть entry-точку в iframe плеера — курс грузится, картинки и стили на месте (то есть
   относительные пути через префикс с токеном работают).
2. Скопировать URL контента и открыть **в новой вкладке**: страница должна работать (токен валиден),
   но `document.cookie` пуст, а `fetch('/api/auth/me')` не возвращает пользователя — это и есть
   доказательство, что sandbox через заголовок работает и без нашего iframe.
3. Подделать один символ в токене → `403`. Дождаться истечения → `403`.
4. Токен от курса A подставить в путь курса B → `403`/`404`.
5. Запросить `../../../etc/passwd` и `../<другой пакет>/index.html` → `404`, в логах нет обращений к S3.
6. Видео в пакете: перемотка даёт `206` с корректным `Content-Range`.
7. В access-логе на месте токена — заглушка.

## Открытые вопросы

1. **Проверять назначение на каждом запросе или только на entry?** Пока выбрано «только entry»
   (подресурсов сотни). Если понадобится мгновенный отзыв — понадобится дешёвый кеш проверки в Redis.
2. **`frame-ancestors`**: наш origin в dev — это `localhost:5173` (vite), а API на `:3000`. Значение
   должно собираться из конфига, а не хардкодиться.
3. **Список инлайновых типов** (что отдаём с `Content-Disposition: inline`) — согласовать с
   whitelist расширений из `02`, чтобы не разошлись.
