# 06. Сквозное тестирование

Родительский план: [2026-07-14-task-scheduler.md](2026-07-14-task-scheduler.md)

**Блокируется:** [01](01-contracts-and-roles.md)–[05](05-realtime-logs.md)
**Блокирует:** ничего — финальная фаза
**Пакет:** —

Каждый подплан уже содержит свой раздел «Проверка» для локальной валидации. Здесь — только сквозные сценарии, которые требуют, чтобы все фазы были реализованы вместе.

## Сценарии

1. Зарегистрировать тестовую задачу → убедиться, что в админке она появилась `paused: true`, без расписания
2. Включить с cron `* * * * *` из админки → задача выполняется на `worker`-роли
3. Перезапустить инстанс с изменённым кодом (без изменения расписания) → `schedule`/`paused`, заданные из админки, не откатываются
4. Запустить `web`-роль отдельно от `worker`-роли → задача НЕ выполняется на `web`, даже если там зарегистрирован handler
5. Запустить 2 инстанса `worker`-роли → задача выполняется только на одном
6. Искусственно замедлить handler дольше TTL лока → продление не даёт второму инстансу перехватить выполнение
7. Убить worker-процесс во время выполнения → run через какое-то время помечается `orphaned`
8. Паузить задачу через admin UI → `worker` пропускает
9. Нажать «Запустить сейчас» → выполнение идёт в процессе `worker`, а не `web`
10. Нажать «Отменить» на выполняющемся run'е → статус `cancelled`, лок освобождён
11. Задаче с `alertOnFailure: true` спровоцировать ошибку → алерт-событие сгенерировано
12. Остановить все worker-инстансы → баннер отсутствия воркеров появляется в разумное время
13. Открыть страницу выполняющегося run'а → логи приходят в реальном времени
14. Убрать задачу из кода, перезапустить → она помечена `stale`, история сохранена
15. Проверить импорты: `packages/platform-core/**` не содержит ни одного импорта из `packages/module-admin/**`
