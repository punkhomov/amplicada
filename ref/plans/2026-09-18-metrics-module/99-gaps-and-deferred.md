# Метрики: что не сделано, недоработано или отложено

Живой реестр: фиксирует текущее состояние на 2026-09-18 (коммит `6009cfd6`, этапы 00–05
закрыты, этап 06 — частично). Назначение — не потерять долги и честно показывать, что
проверено, а что нет. При закрытии пункта — вычёркивать здесь и переносить детали в
`packages/module-metrics/docs/` или `ref/notes/module-metrics.md`.

План и контракты: `00-overview.md`, `01-contracts.md`, `02-offline-stack.md`.

## 2. Недоработано до приемлемого уровня

**UI админки:**
- Правила алертов нельзя редактировать (кроме выключателя): PATCH API есть, формы правки нет.
- Журнал доставки без фильтра по sink и без «повторить»; счётчики очереди — общие на выход.
- Ошибки: нет поиска/фильтров по маршруту/релизу, нет действий «заглушить/закрыть», нет
  графика частоты; samples раскрываются только кликом по строке.
- Web Vitals: только карточки за период, без тренда и разбивки по странице.
- Бизнес: из определения нельзя провалиться в серию с группировкой.
- Панели: только `timeseries`, без фильтров и сохранённых пользовательских дашбордов.
- Net обзорного дашборда (Overview): первая вкладка — сырые «События».
- Вкладок 12 — нет группировки/сайдбара; мобильный вид таблиц не проверялся.
- Настройки: нет предпросмотра эффекта (например «сколько серий добавит такой фильтр»).

**Трекер:**
- Нет `page.leave`/времени на странице; клики только мышью (без keyboard).
- Нет UTM/referrer-разбора на сервере, нет `page.view` длительности.
- `cause`/вложенные ошибки не разворачиваются, стек ≤ 10 кадров.
- `yandex.client_id` не собирается — Measurement Protocol-путь Метрики не работает без него.

**SQL-метрики:**
- Нормализация SQL — регулярками, без парсера (`libpg_query`): сложные запросы (CTE, dollar-quoted)
  могут нормализоваться неточно.
- Нет плана запроса и буферной статистики; exemplars только текст + длительность.

**Алерты:**
- Одна серия на правило (`fingerprint = default`): нельзя «любой роут с p95 > X».
- `forMs` считается от первого наблюдения, а не как непрерывное окно: после пропуска оценки
  правило может сработать раньше.
- Нет silences/inhibition/повторов, нет аномалий и burn-rate.
- Значения измерений приводятся к мс, но для CLS (0..1) это не показано в UI — можно
  ошибиться с порогом.

**Приватность:**
- k-anonymity в UI не применяется (нет разбивок по людям, которые стоило бы скрывать, но при
  появлении таких представлений правило нужно).
- Opt-out — только флаг/браузерные сигналы; у пользователя нет видимой кнопки.
- Аудит изменений (кто менял правила/настройки/выходы) не ведётся: только `updated_at`.

## 3. Осознанно отложено (deferred) с причинами

- **Воронки/retention** — D-013: сначала данные и панели.
- **ClickHouse и любой внешний аналитический стек** — владелец просил не покидать платформу;
  пороги и путь описаны (`explanation/scaling.md`).
- **Пользовательская страница opt-out** — нет места в оболочке (нет раздела настроек).
- **`pg_stat_statements`** — не всегда доступен в закрытых контурах, нужны права.
- **Живой прогон Яндекс.Метрики** — нет счётчика/OAuth; покрыт юнит-тестами (D-018).
- **SSE-реалтайм** — polling достаточен (D-007).
- **Хранение секретов в БД** — секреты только через core `secrets` (D-003, D-016).

## 4. Эксплуатация и инфраструктура

- `metrics.maintenance` **не активна по умолчанию**: расписание включается вручную в
  `/admin/tasks`; fallback — `ensurePartitions()` в `start()`. Нет алерта «партиция
  кончается» и нет автоматической активации расписания.
- Диспетчер очереди, оценщик алертов и health-счётчики не рассчитаны на мультипроцессный
  деплой (`ROLE=worker`): возможны дубли отправки, счётчики «на процесс» (D-019).
- Нет CI-пайплайна (общий техдолг проекта) и нет интеграционных тестов с БД
  (`bootstrap` + `app.inject()`); покрытие — юнит-тесты (53).
- Нет сборки VitePress для `packages/module-metrics/docs/`; штампы `verified_commit` в docs
  указывают на коммит до реализации пакета (`9e0cfb80`) — обновить при следующем проходе.
- Ретеншн удаляет партиции, но глобальные счётчики/агрегаты «сколько всего событий» считать
  нельзя после удаления — по дизайну.

## 6. Известные несогласованности и грабли

- **Три маркера «неизвестной» размерности**: HTTP `<unmatched>`, SQL `<unattributed>`,
  vitals `<unattached>` — свести к одному при следующем касании.
- Тексты ошибок/алертов частично английские (сообщения в БД), UI локализован — бэкенд-i18n нет.
- `id` события обязан быть uuid (жёстко): внешние источники потребуют отдельной колонки.
- Валидация атрибутов режет ключи без точечной нотации (исправлено, но правило стоит помнить).
- `web-vitals` запиннен на 6.2.1 из-за `minimumReleaseAge` (исключения не расширяем).
- `minimumReleaseAge` заблокирует свежие версии зависимостей — проверять возраст перед `pnpm add`.
- `pkill -f "<script>"` убивает собственный шелл — только bracket-трюк (уже в AGENTS.md).

## 7. Предлагаемый порядок следующих работ

1. **Воронки и retention-когорты** (+ UI) — единственный крупный функциональный пробел
   плана; нужен запас сырья ≥ 30 дней.
2. **Редактирование правил алертов и DLQ-replay в UI** — маленькие, закрывают раздел 2.
3. **Реальный браузерный прогон** трекера/ошибок/панелей и opt-out — снять вопросы матрицы.
4. **Обзорная вкладка** (карточки: события, ошибки, p95, алерты) — вход в модуль.
5. **Мультипроцессная защита** (SKIP LOCKED / worker-роль) — когда появится `ROLE=worker`.
6. **Интеграционные тесты** `bootstrap`+`inject` и CI — общий техдолг, но метрики без них
   растут вслепую.
